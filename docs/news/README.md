# Добавление новостей через CMS

Новости управляются в существующей Strapi CMS. Отдельная регистрация администратора на публичном сайте не используется.

## Работа редактора

1. Откройте `/cms` на адресе вашего сервера и войдите как администратор CMS.
2. В **Content Manager → Новости / News** нажмите **Create new entry**.
3. Заполните `title` (заголовок), `slug` (латинский адрес, например `new-factory`), `locale_code` (язык) и `summary` (анонс, до 1200 символов). В `body` добавьте текст, заголовки, списки и ссылки. HTML и вставка внешних изображений в текст запрещены.
4. При необходимости выберите `cover` в Media Library, заполните `cover_alt` (описание изображения), `topic`, `publication_date`, `seo_title` и `seo_description`. Если дата не задана, сайт использует дату публикации.
5. **Save** сохраняет черновик в PostgreSQL. Он не появляется в публичном списке, на главной или по адресу новости.
6. Пользователь с правом **Publish** публикует запись. Новость появляется на главной (три последних), в `/news` и `/news/<slug>` без пересборки фронтенда.
7. Изменения опубликованной новости сначала сохраняются в черновике. Публичная версия остается прежней до следующего **Publish**. **Unpublish** снимает запись с публикации; черновик сохраняется.

Язык выбирается для каждой записи явно. `/en/news` читает только опубликованные записи `en`; переводы не создаются автоматически. Slug уникален в коллекции, поэтому для языковых вариантов используйте разные адреса.

## Роли и изображения

В **Settings → Administration Panel → Roles** для News назначьте редактору **Read / Create / Update** с нужными полями; издателю добавьте **Read / Publish**. Для загрузки обложек отдельно выдайте права Media Library на просмотр и создание. Не выдавайте права управления пользователями или бизнес-каталогом без необходимости. Super Admin имеет полный доступ.

Бизнес-аккаунты, API JWT покупателя и публичные посетители не дают доступ к CMS. При каждой записи сервер повторно проверяет действующий сеанс CMS, актуальные роли и права полей. Сохранение и публикация фиксируются в журнале с идентификатором CMS администратора.

Обложки: локально загружаемые PNG / JPEG / WebP, максимум 1 MiB и 16 мегапикселей. Используется существующая обязательная проверка ClamAV, декодирование и повторное кодирование изображения. При недоступности сканера загрузка закрыта. Вставка URL и загрузка SVG / HTML не разрешены.

Важно: Media Library хранит проверенные файлы в публичном `/uploads`. Знание URL позволяет открыть файл даже до публикации статьи. Не загружайте конфиденциальные материалы. Черновой текст и данные записи доступны только администраторам с соответствующими правами.

## Самостоятельный сервер

- PostgreSQL хранит записи, черновики, публикации и роли CMS.
- Постоянный volume Media Library хранит обложки; включайте его в резервное копирование вместе с БД.
- У фронтенда должен быть `API_INTERNAL_BASE_URL=http://backend:8000/api/v1` (или адрес backend в вашей сети). `NEWS_SOURCE=api` включает CMS явно и является режимом по умолчанию для подключенного сервера.
- Reverse proxy направляет `/api/v1/*`, `/content-manager/*`, `/upload*`, `/uploads/*` и нативные CMS endpoints на Strapi; `/news*` остается Next.js.
- Только статические ознакомительные сборки используют `NEWS_SOURCE=static`, `ALAGEUM_PUBLIC_ONLY=1` или существующий `PAGES_STATIC_PREVIEW=1`. При ошибке рабочего API архив не подставляется вместо актуальных данных.
- Список принимает только `locale`, `page`, `page_size` (до 50); детализация только `locale`. `status=draft`, `populate`, произвольные filters и публичные записи запрещены. Публичные ответы всегда `no-store`.

## Проверка

- `cd backend-node && node --test tests/news.test.js`
- `cd frontend && node --test tests/news.test.mjs`
- `cd backend-node && bash scripts/run-news-tests.sh`

Интеграционный запуск сам создает изолированный PostgreSQL и не использует внешнюю `DATABASE_URL`. Нужны Node 24 и PostgreSQL 16/17; `PG_BIN` может указывать на каталог бинарных файлов. Он проверяет создание, повторное чтение черновика, отдельные права редактора/издателя, сканирование обложки, отказ EICAR/недоступного сканера, публикацию, безопасное редактирование, снятие с публикации, отсутствие утечки черновика, неверные роли/сеансы и аудит. Сканер в этом тесте является контролируемым протокольным fixture; отдельная эксплуатационная проверка настоящего ClamAV обязательна для запуска сервера.
