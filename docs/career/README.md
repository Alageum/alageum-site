## Структура до / после

| Было | Стало |
|---|---|
| `/careers` — направления, среда, команда, публикации, отклик | `/careers` — работа в группе, профессии, рабочая среда, развитие и переход к вакансиям |
| `/careers/about` | переход → `/careers` |
| `/careers/team` — список руководителей, повтор «Компании» | переход → `/careers#workplaces`; вместо повторного списка — реальные сотрудники на производственных фотографиях |
| `/careers/workplaces` — повтор списка предприятий | переход → `/careers#workplaces`, ссылка на существующий каталог предприятий |
| `/careers/learning` | переход → `/careers#learning` |
| `/careers/internships` | отдельная задача: первый опыт, направления программы, подготовка обращения |
| `/careers/process` | переход → `/careers/apply#preparation` |
| `/careers/vacancies` | каталог с поиском, фильтрами направления и статуса; старые публикации отделены от открытых вакансий |
| `/careers/vacancies/[id]` | сохранены ID, задачи, требования; видимый неподтверждённый статус и вопросы об условиях |
| `/careers/apply` | подготовка письма, локальное резюме и черновик, вопросы перед отправкой |

Переходы реализованы через `permanentRedirect`. При потоковом ответе Next может передавать перенаправление внутри HTTP 200; для безусловного HTTP 308 до рендера подготовлен `redirects.json` для общего `next.config.mjs` / reverse proxy (общий файл не изменялся).

Те же переходы работают с `/en` и `/kk`, включая якоря. Используется общая навигация сайта; дополнительное меню раздела удалено. Существующие ссылки общей шапки и футера остаются рабочими через перенаправления.

## Источник вакансий и CMS

В исходной реализации нет специализированного CMS-типа вакансии и нет серверного приёма откликов. Источник каталога — `frontend/lib/ecosystem/careers.js`, две позиции из официальной публикации. Сохранённые материалы: `frontend/lib/public/materials/ru-karera-aktualnye-vakansii.json` и `ru-karera-stazhirovki-dlya-studentov.json`, дата выгрузки 13.10.2026. Официальные страницы повторно просмотрены 01.11.2026; отсутствие даты закрытия не подтверждает открытый статус. Позиции имеют `status: unverified`, `checkedAt: 2026-11-01`. Поэтому вкладка актуальных вакансий честно пуста. Никаких новых вакансий, зарплат и льгот не добавлено.

Общий редакционный CMS-контракт `/pages/[locale]/[slug]`, API `frontend/lib/api/pagesServer.js` и данные backend сохранены. Живая БД CMS не была доступна для сверки опубликованных записей; утверждение об отсутствии специального типа основано на исходниках текущего checkout. Изменённые страницы и раньше не читали CMS API. Перед публикацией нужна проверка владельцем данных и подключение актуального реестра HR.

## Форма

Данные не отправляются на сервер. Черновик хранится в localStorage, резюме — в IndexedDB. Сохранение показывает только подтверждение локального сохранения. Подготовка письма открывает `mailto:cv@alageum.com`; файл необходимо прикрепить вручную. Даже после открытия почты интерфейс явно говорит «Отклик ещё не отправлен». Проверяются обязательные поля, email, непустое имя, расширение PDF/DOC/DOCX, ненулевой размер и лимит 5 МБ. Это не серверная проверка содержимого файла и не антивирус. Закрытая позиция имеет отдельное состояние и переводит к инициативному отклику. Неизвестный ID показывает штатную страницу «не найдено». В dev проверен HTTP 404; production при потоковом рендеринге возвращает HTTP 200 — см. ограничение ниже.

Тестовые данные синтетические (`example.test`), письма HR не отправлялись. Приватные сведения не добавлены в исходники.

## Объединение: общие изменения для владельца проекта

Не выполнялись в этой ветке:

1. В `frontend/components/SiteHeader.js` и `frontend/components/SiteFooter.js` заменить старые пункты в шапке/футере на четыре основных: работа в группе, вакансии, студентам, отклик.
2. В общем sitemap/canonical и внешних закладках предпочтительны новые адреса; переходы для существующих локальных адресов уже реализованы в careers `[slug]`; правила HTTP 308 из `redirects.json` подготовлены для объединения.
3. Legacy Joomla-адреса `/ru/karera/aktualnye-vakansii`, `/kz/karera/stazhirovki-dlya-studentov` и аналоги следует направить на новые маршруты на уровне общего routing/reverse proxy. Они не были локальными маршрутами этого раздела. CMS-страницы материалов оставлены без изменений.
4. При серверном приёме откликов нужен реальный контракт API: приём файла, валидация, политика хранения, идентификатор подтверждённой заявки и только после ответа — успех. Сейчас этот интерфейс не имитирует интеграцию.
5. Для настоящего HTTP 404 в production добавить в `frontend/proxy.js` проверку `/careers/vacancies/:id` и локализованных аналогов по тому же реестру вакансий до начала потокового рендера. Сейчас production отвечает HTTP 200 со страницей «не найдено»; не считать dev-тест доказательством production-статуса.
6. Новые переводы изолированы в `components/careers/translations.json`, существующий общий словарь сохранён. Перед публикацией необходима редакторская вычитка EN/KK.

## Проверка

Команды из `frontend` (Node 24):

```sh
npx eslint 'app/(site)/careers' 'app/[locale]/(site)/careers' components/careers components/ecosystem/CareerApplication.js components/ecosystem/VacancyDirectory.js lib/ecosystem/careers.js e2e/careers-redesign.spec.js playwright.career.config.js
node --test tests/ecosystem-domain.test.mjs tests/public-content.test.mjs tests/photography.test.mjs
npx playwright test --config=playwright.career.config.js
```

В браузерных тестах: desktop Chromium, мобильный viewport iPhone 13 в Chromium; переходы кандидата, поиск/фильтры, пустые результаты, неизвестный ID, обязательные поля, тип и размер файла, IndexedDB, скачивание, повторная загрузка, удаление, ошибка хранилища, EN/KK, старые URL и reduced motion. Мобильный Chromium не заменяет проверку настоящего iOS Safari.

Результаты 01.11.2026:

- ESLint для всех изменённых JS-файлов: успешно, без ошибок.
- `node --test` по трём указанным наборам: **21/21**.
- Playwright: **6/6 сценариев** (по три на desktop и mobile, запуски последовательно). Последний desktop-прогон: 3/3, 1,1 минуты. Mobile: путь кандидата и отказ хранилища 2/2, редиректы/языки/reduced motion/404 — 1/1 отдельным запуском.
- Production build: **успешно**, Next 16.3.8, Turbopack, 1229 статических страниц всего проекта. Команда `ALAGEUM_PROFILE_BUILD=1 NODE_OPTIONS=--max-old-space-size=2048 npm run build`; использована существующая настройка отдельного `distDir: .next-profile`, общий конфиг не изменялся.
- `git diff --check`: успешно.

В ходе проверки исправлены преждевременные клики по ещё не активированным фильтрам: до гидратации кнопки отключены. Для неизвестных ID добавлены `dynamicParams: false` и перечень существующих ID. В dev проверен HTTP 404, однако production smoke обнаружил HTTP 200 с интерфейсом «не найдено»: эти настройки не гарантируют статус до начала потока. Нужна проверка ID до рендера в общем `frontend/proxy.js`, который по границам задачи оставлен без изменений. Проверены локальное сохранение и скачивание резюме, удаление, отклонение TXT и файла больше 5 МБ, ошибка хранилища и отсутствие отправки в HR. Подготовка письма оставляет явный статус «Отклик ещё не отправлен».

Файлы перечислены в `changed-files.md`, правила перенаправлений для общего конфига — в `redirects.json`. Скриншоты — `screenshots/`: полные страницы на desktop и mobile, отдельно первые экраны production-сборки. Физический телефон и Safari не проверялись. Живая CMS-БД не проверялась. Публикация требует подтверждения прав на изображения и актуальных данных HR.

Production smoke на localhost:3102: главная и существующая позиция — HTTP 200; неизвестные ID RU/EN — HTTP 200 (описанное ограничение). На главной desktop/mobile ошибок JavaScript не было. Финальные первые экраны сохранены из production-сборки.

Состояние «закрыта» реализовано в карточке позиции и каталоге; реальной закрытой записи в текущем источнике нет, поэтому end-to-end с подтверждённой закрытой вакансией не выполнялся.
