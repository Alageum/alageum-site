# ALAGEUM: передача кода администратору

Это исходный комплект для самостоятельного развёртывания. Он не переключает
домен, не создаёт учётные записи на внешних сервисах и не содержит рабочих
паролей. Точный исходный коммит и SHA-256 ZIP указаны в сопроводительном файле
передачи. Распакуйте весь архив: проверяемые исходные медиа нужны при сборке.

## 1. Какой стек запускать

Активный вариант: `deploy/compose.production.yml` и только он.
Он включает Next.js, Node.js/Strapi, PostgreSQL 17, ClamAV и Nginx.
Не смешивайте его с корневыми `docker-compose.yml`, `docker-compose.node.yml`,
Makefile или старыми инструкциями из `README_HANDOFF.md`: это исторические/dev
материалы. Vercel для этого комплекта не нужен.

Нужны Linux x86_64, Docker Engine/BuildKit, Compose 2.30+, Bash, Python 3.11+,
OpenSSL, curl; ориентир памяти — от 8 GiB, больше при одновременной сборке.
Node 24.x нужен для локальных проверок вне контейнеров.

## 2. До запуска

Пройдите разделы 2–4 [полного руководства](server-deployment.md):

1. Выберите домен и подготовьте HTTPS-сертификат, отдельный доверенный TLS CA
   и сертификат PostgreSQL с SAN `DNS:postgres`.
2. Скопируйте `deploy/.env.example` в `/etc/alageum/stack.env`, а
   `deploy/backend.env.example` в `/etc/alageum/backend.env` вне checkout.
   Заполните точный релиз, пути и домен. Секреты выдаёт уполномоченный оператор;
   значения не пересылаются в чат и не коммитятся.
3. Подготовьте постоянные каталоги/владельцев и два разных пароля PostgreSQL
   точно по руководству. APP_KEYS, JWT/административные ключи и соли независимы.
4. Укажите согласованный SMTP с TLS и From-доменом. Проверьте SPF/DKIM/DMARC
   и доставку в разрешённый тестовый ящик до публичной регистрации.
5. Проверьте отсутствие пересечения фиксированных сетей. Наружу публикуются
   только 80/443. БД, scanner и внутренние порты приложения не открываются.

На новой БД каталог и новости не появятся автоматически. Импорт/редакторское
наполнение и перенос существующих данных — явные отдельные действия оператора.

## 3. Закрытая проверка

Работайте сначала в изолированной staging-среде, не с production-данными.
Последовательность команд и обязательных preflight-проверок приведена в разделе 4
[руководства](server-deployment.md#4-сборка-и-закрытая-приёмка).

Минимальная последовательность:

```sh
./deploy/compose.sh /etc/alageum/stack.env config --quiet
./deploy/scripts/check-config.sh /etc/alageum/stack.env
./deploy/compose.sh /etc/alageum/stack.env build --pull backend frontend
./deploy/compose.sh /etc/alageum/stack.env up -d --wait --wait-timeout 1200 postgres clamav
./deploy/compose.sh /etc/alageum/stack.env run --rm --no-deps --entrypoint node backend scripts/check-production-readiness.js
./deploy/compose.sh /etc/alageum/stack.env run --rm --no-deps --entrypoint node backend scripts/check-media-scanner.js
./deploy/compose.sh /etc/alageum/stack.env up -d --wait --wait-timeout 300 backend frontend
./deploy/compose.sh /etc/alageum/stack.env up -d --wait proxy
```

Не публикуйте вывод полного `docker compose config`: в нём могут быть секреты.
Не используйте `curl -k`, отключение TLS, demo-аккаунты или заглушку антивируса.
Зелёный `/healthz` или `/readiness` сам по себе не доказывает доставку писем,
сохранность файлов или восстановление.

## 4. Первый администратор и данные

CMS-администратор и бизнес-пользователь — разные контуры прав.
Публичное создание первого CMS-администратора закрыто.
Создайте его только из доверенного операторского терминала:

```sh
./deploy/compose.sh /etc/alageum/stack.env exec backend node node_modules/@strapi/strapi/bin/strapi.js admin:create-user
```

CLI запрашивает пароль скрытым вводом. Не передавайте пароль флагом командной
строки. CMS доступна по `/cms`, бизнес-интерфейс каталога по `/admin/catalog`.
Первый бизнес-пользователь проходит обычную регистрацию и email-подтверждение;
права выдаются отдельной `provision-business-operator.js` после проверки точных
пользователя, компании и полномочий. Команды dry-run и apply описаны в руководстве.

Импорт reference-каталога: сначала `bootstrap-reviewed-catalog.js` без `--apply`,
затем только после проверки/разрешения `--apply` в пустой каталог. Существующая
БД не перезаписывается. Новости создаются и публикуются редактором в CMS.

## 5. Приёмка и эксплуатация

Перед открытием трафика проверьте на настоящем HTTPS-origin:

- публичные RU/KK/EN страницы, каталог, CMS и роли;
- регистрация → письмо → подтверждение → вход, повторная загрузка и выход;
- сброс пароля с настоящим письмом и отзыв старой сессии;
- чистая загрузка изображения и отклонение EICAR настоящим ClamAV;
- сохранение БД/файлов после пересоздания контейнеров;
- парный backup и восстановление в новую пустую изолированную цель;
- недоступность внутренних портов извне, корректный TLS и proxy/CSRF-защиту.

```sh
./deploy/scripts/backup.sh /etc/alageum/stack.env /absolute/existing/private/backups
./deploy/scripts/restore.sh /etc/alageum-rehearsal/stack.env /absolute/backup --restore-empty-target
```

Backup включает короткое окно недоступности. Restore ничего не удаляет и после
успеха оставляет приложение выключенным. Восстановленную копию проверяйте с
изолированным SMTP, чтобы очередь не отправила реальные старые письма.
Секреты, off-host backup, retention, мониторинг диска/TLS/почты/ClamAV и rollback
настраиваются отдельно по разделам 5–7 полного руководства.

## 6. Честные границы

- eGov/ЭЦП и Google-вход отключены. Наличие кода адаптеров не подтверждает
  реального провайдера, сертификаты, договорённости или подпись документов.
- Статический preview — только просмотр, не серверное приложение или CMS.
- Часть исторических доказательств/approval и исходный большой PDF не входят
  в полноценную текущую приёмку. Не переписывайте хеши ради зелёных тестов.
- Свежие результаты тестов и dependency audit, включая оставшиеся проблемы,
  смотрите в [отчёте комплекта](release-2026-10-23/README.md).
  Проверки от 19 октября в полном руководстве относятся к указанному там старому
  коммиту, а не автоматически к обновлённым зависимостям этого комплекта.
