## Implemented

- PostgreSQL-backed rolling admission limits shared across replicas, bounded
  identity allocation, database-clock expiry and fail-closed database errors.
  Password/browser/Google entry, registration, refresh, native CMS entry and
  quote creation use the shared boundary.
- Exact trusted-proxy address resolution, strict CMS credential shape and the
  existing HttpOnly cookie/Origin/session-generation boundaries.
- TLS-required SMTP adapter checks, encrypted durable outbox lease fencing,
  retry/expiry behavior and explicit operator-bootstrap safeguards.
- Scanner-gated public raster uploads, private parser/quarantine cleanup and
  explicit persistent local public-root configuration. Native binary replacement
  is safely unavailable; users can upload a new image and edit metadata.
- Read-only production configuration/storage diagnostics with safe identifiers.
  Configuration strings and local directory checks do not certify deployment,
  persistent mounts, service health or backup/restore.
- Current-source legacy behavioral evidence and complete schema inventory,
  without changing the archived historical approvals.
- Public-page/catalog test repairs and a ZOM/ZNOM navigation classifier fix;
  automatic model startup, pixel checks and the handed-off display design remain.

## Concrete release work

1. Supply the intended domain, reviewed HTTPS/same-origin proxy topology and
   exact trusted proxy peers. Run real cookie login/logout and account flows at
   that origin.
2. Inject independent secrets outside Git and provision the isolated PostgreSQL
   service. Rehearse backup restore, schema startup/restart and rollback.
3. Select an approved SMTP sender/provider, configure it securely, verify real
   verification/reset delivery to a separately authorized recipient, and monitor
   the outbox. No real mail was sent by these tests.
4. Provision ClamAV with current signatures on a restricted local/private
   endpoint. Execute the clean/EICAR diagnostic in that environment.
5. Mount the explicit app-owned persistent public-media root and separate
   private quarantine. Verify filesystem checks, service restart, volume
   persistence and backup/restore. Merely naming a directory does not prove a
   durable mount.
6. Resolve or explicitly review the documented dependency advisories and the
   remaining historical catalog-release evidence. Restore the excluded original
   transformer PDF through an authorized transfer before promising that download.
7. Run exact-commit acceptance and approve cutover. Only then can a separately
   reviewed release change replace the current production interlock with the
   validated deployment conditions. There is no boolean bypass flag.
