# ALAGEUM — актуальная передача разработки

Дата: 13 октября 2026. Это чистая Git-копия текущего рабочего дерева с последними незакоммиченными изменениями. Старая Git-история не отправлена. Последний исходный коммит: 38ee4bb8706ef5bbce1cc5d9eab548912d2dbd2a. Список локальных изменений: handoff/working-tree-status.txt.

## Актуальная архитектура

- **frontend/**: Next.js 16.3.8, React 19.2, Node.js 24; основной сайт, каталог, локальные подборки/заявки, карьера и интерфейсы кабинета.
- **backend-node/**: актуальный Node.js 24 + Strapi 5.56.0 backend. PostgreSQL 16+; CMS `/cms`, API `/api/v1`, плагин каталога `/cms/plugins/alageum-catalog`.
- **backend/**: прежний Python/FastAPI backend, сохранён для истории и совместимости. НЕ выбирать его для нового запуска и НЕ использовать его базу для Strapi.
- **Design/**: Design Panel/styleboard. Открыть `Design/index.html` локально или запустить отдельный статический сервер в этой папке. Токены — design-tokens.json; логотипы и ресурсы — assets/.
- **frontend/public/**: локальные изображения, видео, шрифты, партнёры, документы и каталожные ресурсы. Оригинальный каталог трансформаторов (~805 MiB) по указанию пользователя исключён из Git; остальные необходимые локальные ресурсы включены.
- **frontend/lib/catalog/**: активные статические товары, характеристики, связи вариантов, редакционный overlay и защищённые источники.
- **frontend/lib/public/**: корпоративный контент, новости, материалы, предприятия и партнёры.
- **backend-node/data/**: проверенные публичные фикстуры импорта, схемные привязки, зеркала разрешённых ресурсов и частный редакционный пакет каталога.
- **backend-node/src/api/**: Strapi схемы; **backend-node/src/domain/** и **backend-node/database/migrations/**: миграции/ограничения приложения. Исторические Alembic миграции — backend/alembic/.
- **docs/**: спецификации, история проверки и документация миграции; **scripts/**: инструменты импорта; **.github/**, Dockerfile, docker-compose*.yml, infra/, vercel.json: имеющиеся конфигурации доставки.

## Версии и требования

Node.js **24.x**, использовался **24.21.0**; npm из Node 24. Lock-файлы обязательны — устанавливать `npm ci`. PostgreSQL **16+** (локально postgres:16-alpine). Docker Engine/Compose v2 нужен только для Docker-сценария/локальной БД. На Linux могут понадобиться python3, make, g++ для нативных зависимостей. Python backend для основного локального просмотра не нужен.

## Быстрый просмотр сайта без базы

Из распакованного корня:

```bash
node --version
cd frontend
npm ci
npm run dev -- --hostname 0.0.0.0
```

Открыть http://127.0.0.1:3000/. Другие компьютеры в том же роутере: `http://IP_КОМПЬЮТЕРА:3000/`. Адрес 192.168.123.4 относится к предыдущему компьютеру, не является универсальным. Если Next.js блокирует dev origins на новой машине, в `frontend/next.config.mjs` заменить/добавить только нужный локальный IP в `allowedDevOrigins` и перезапустить. Не задавать `NEXT_PUBLIC_CATALOG_SOURCE=api` для этого сценария: публичный каталог сейчас использует безопасный файловый snapshot и catalogEditorialOverlay.json. `/company` использует static по умолчанию.

Для самостоятельной frontend production-сборки (не запускавшейся ради этой упаковки): `npm run build`, затем `npm run start -- --hostname 0.0.0.0`. Если build останавливается на проверках источников/контекста, прочитать docs и существующие scripts; НЕ отключать защиту и НЕ подменять hashes ради прохождения.

## Запуск актуальной админки с новой отдельной локальной БД

Команды для Linux/macOS bash; находиться в распакованном корне. НЕ копировать настоящие секреты с прежнего компьютера. Генератор создаёт новые случайные ключи в файле ВНЕ проекта, запрещает перезапись существующего файла. Второй аргумент — IP для доступа из локальной сети; для одного компьютера можно использовать 127.0.0.1.

```bash
node handoff/create-local-env.mjs ../alageum-local.env 127.0.0.1
export ALAGEUM_HANDOFF_ENV="$(cd .. && pwd)/alageum-local.env"
docker run -d --name alageum-handoff-postgres \
  --env-file "$ALAGEUM_HANDOFF_ENV" \
  -p 127.0.0.1:55432:5432 \
  -v alageum_handoff_pg:/var/lib/postgresql/data postgres:16-alpine
docker exec alageum-handoff-postgres pg_isready -U alageum_strapi -d alageum_strapi_handoff
# Дождаться "accepting connections"; иначе повторить последнюю команду.
set -a
source "$ALAGEUM_HANDOFF_ENV"
set +a
cd backend-node
npm ci
npm run build
npm run start
```

Админка: http://127.0.0.1:8000/cms. Для LAN передать генератору реальный IP вместо 127.0.0.1 и открыть `http://IP:8000/cms`. Порт БД остаётся только на loopback. Первый администратор регистрируется на экране Strapi; логина/пароля в архиве нет. Админка проверялась на экране регистрации, сценарии нового пользователя/редактирования после этого запуска ещё не проверены. Не публиковать локальный dev backend в интернет.

Повторный запуск БД: `docker start alageum-handoff-postgres`, далее загрузить тот же env и `npm run start` в backend-node. Не генерировать ключи заново для уже созданной базы. Остановка: Ctrl+C для серверов, `docker stop alageum-handoff-postgres`. Не удалять volume для сохранения локальных изменений.

Есть самостоятельный `docker-compose.node.yml`: он собирает Node backend и API-вариант frontend и требует приватный NODE_ENV_FILE. Инструкция — docs/node-strapi-migration.md. Не объединять его с прежним docker-compose.yml и не запускать вторую frontend-службу на занятом порту 3000. В Compose порты по умолчанию loopback. Native backend схема и seed стартуют автоматически; production APP_ENV намеренно запрещён текущими проверками.

## Окружение

Корневой `.env.example` содержит имена переменных, безопасные значения и ПУСТЫЕ секреты. Там основной набор, legacy-переменные и полный список обнаруженных параметров сборки/проверок. Отдельные frontend/.env.example и backend-node/.env.example описывают актуальные runtime-наборы. Не загружать корневой шаблон вслепую: заполнять только нужные параметры. Никакие настоящие env, SSH/API ключи или токены не переданы. `handoff/create-local-env.mjs` — удобный независимый генератор только локального Node-окружения.

CMS и Next `/admin/catalog` — разные интерфейсы и аутентификация. `/admin/catalog` требует совместимого API и прав бизнес-пользователя; создание Strapi администратора не создаёт такой аккаунт. Не включать демонстрационное seeding в рабочей базе.

## Последние изменения, которые нужно сохранить

1. Главная: локальное видео с HD/mobile/4K версиями; исправлены muted autoplay и повтор при canplay. 4K — пространственный upscale, не AI-реконструкция.
2. Партнёры: все 12 карточек с фактами/галереями; две независимые зоны удержания; слой не мешает выбирать соседние логотипы; ручная горизонтальная прокрутка, цвет при выборе, пауза движения.
3. Предприятия: справка возле города, переворот у края экрана; карта без затемнения; закрытие при уходе далеко от маркера/карточки даже внутри карты. 220 ms для перехода.
4. Карта: серый градиент, крупная надпись КАЗАХСТАН Helvetica Bold. Зелёные CSS оттенки заменены нейтральными серыми, красный бренд сохранён.
5. Основные заголовки/навигация: Helvetica Bold (700), fallback Arial. Helvetica не приложена отдельным лицензированным шрифтом; фактический font зависит от устройства. Остальные существующие локальные шрифты включены.
6. Logo: первый вариант из lettering; переход всегда на корпоративную главную. Навигация Каталог и Карьера ведёт на их главные страницы.
7. Повторяемые исходные данные решений сохранены, добавлены динамические появления; новости с локальными фото, крупные показатели/графики не дублируют смысл.
8. Редакционный импорт каталога идемпотентен, конфликтные изменения сохраняются, новые материалы не публикуются автоматически.

## Что не закончено и известные ограничения

- Production-развёртывание, домен/TLS, реальные CRM/HR/RFQ/почтовые интеграции и полноценная коммерческая backend эксплуатация не выполнены. APP_ENV=production в Node намеренно блокируется до решения заявленных архитектурных ограничений.
- Корпоративные публичные страницы по умолчанию не читают CMS. Для ограниченного `/company` opt-in существует COMPANY_SOURCE=cms, API_INTERNAL_BASE_URL, PAGES_SITE_ORIGIN; сначала читать docs/node-strapi-editorial-pages.md и docs/node-strapi-editorial-validation.md. Миграция остальных страниц в CMS не завершена.
- Полный набор тестов нельзя считать зелёным: исторические проверки source approval hashes могут быть устаревшими после UI изменений. НЕ подделывать hashes/approval. Предыдущие точечные проверки проходили, но для упаковки тесты/сборка НЕ выполнялись.
- Некоторые фото не подтверждены: 334 записи без подтверждённого визуального материала, 251 с типовыми ориентирами, 9 только с видеокадрами; права 221 нового кандидата не подтверждены. Есть 18 решений по названиям и 14 вопросов единиц/происхождения. Открытые вопросы сохранены в handoff/catalog-update-reports/.
- Substations-local-edition.pdf — восстановленное локальное издание 104 стр., не исходный издательский PDF; transformers-2026-original.pdf — оригинал 187 стр. Юридические и картографические источники сохраняются.
- EN/KZ контент требует редакционной проверки. Не считать машинные варианты утверждёнными.
- Телефоны, адреса, имена в публичных корпоративных материалах — публичный контент; это не клиентские аккаунты. Имя/пароль нового админа и персональные заявки НЕ включены.
- README и некоторые исторические docs могут описывать предыдущие состояния/числа. Для актуальной архитектуры этот README_HANDOFF приоритетен, технические ограничения кодовых проверок сохраняются.

## Проверка архива

handoff/GIT_TRANSFER_NOTES.json описывает проверку доступа и исключения. handoff/GIT_FILE_MANIFEST.json содержит размеры и SHA-256 отправляемых файлов (кроме самого манифеста/аудита). handoff/GIT_SECURITY_AUDIT.json — результат проверки именно staged-файлов. Исключены зависимости, build/dist, .next*, кэши, test-results, логи, .git, реальные env, DB/дампы пользовательских таблиц и пользовательские uploads/storage. Публичные материалы/фикстуры и исходный тестовый код сохранены; синтетические test-only значения в тестах/CI не являются работающими ключами.

Ничего в исходном проекте ради упаковки не менялось. Откройте frontend/AGENTS.md перед изменениями; используйте Design Panel и существующие компоненты. Не пересоздавать реализованные media-фильтры/3D и не менять редакционный импорт при UI правках.
