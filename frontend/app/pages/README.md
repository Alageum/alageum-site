# Editorial Page delivery

This slice was reimplemented from visible requirements and verified repository content after unpublished files were lost. It is not an exact restoration, and earlier test results do not establish this checkout's correctness.

`/pages/[locale]/[slug]` is a controlled text template. `/company` keeps its rich static presentation by default and can explicitly select this same template as authoritative CMS content. It adds no replacement navigation. Supported locale codes are exactly `ru`, `kk`, `en`, `zh`, and `uz`, with no fallback or fabricated translations. The article carries its content language; the shared existing shell remains Russian.

The server-only loader calls `GET {API_INTERNAL_BASE_URL}/pages/{slug}?locale={locale}`. `API_INTERNAL_BASE_URL` must explicitly end in `/api/v1`, without credentials, query or fragment. Requests omit auth and cookies, use `cache: no-store` and `redirect: error`, time out after five seconds, and stream at most 512 KiB of JSON. Only a 404 becomes `notFound()`; invalid route parameters are absent without an API request. Other errors remain errors and never select bundled content. Payloads require matching slug/locale, published timestamps, exact public fields and bounded valid native Blocks.

React escapes all text. The template owns the only h1; body h1 Blocks render as h2. Paragraphs, headings, native lists, quotes, code, inline marks and safe HTTP(S), mail, phone, root-relative and anchor links are supported. Raw HTML, media, unknown fields/types, unsafe links and malformed nesting fail closed. The renderer fetches no media. Limits are 200 top-level blocks, 200 children per node, depth 8, 2,000 nodes and 100,000 text characters.

Metadata is explicitly `noindex, nofollow`. Generic pages emit an own-route canonical only when `PAGES_SITE_ORIGIN` explicitly identifies the deployment origin; otherwise it is omitted. With `COMPANY_SOURCE=cms`, `/company` and exactly `/pages/ru/about` both require that valid explicit origin and canonicalize to its `/company` URL. No production origin, redirects or translated alternates are inferred.

`COMPANY_SOURCE` is server-only: unset or exact `static` preserves the complete original company component and metadata with zero Page API reads and no backend configuration. Exact `cms` selects only published locale `ru`, slug `about`, requires `PAGES_SOURCE` unset or `api`, and rejects `PAGES_STATIC_PREVIEW=1`. Every other supplied company value, including empty, fails. Query strings and cookies cannot select it. Invalid company configuration is checked only for `/company` and the exact alias, leaving unrelated generic pages independent. CMS missing/draft/unpublished content is hard404; upstream, payload, timeout or configuration errors are hard500, with no rich static or fixture fallback.

Existing routes and the homepage retain the URL-transparent `(site)` group and its original loading boundary. `/company` and generic editorial routes live outside that group, without an ancestral loading boundary that could stream 200 before a missing-page/error decision. The root layout and every other route remain unchanged. The complete static company component is extracted to `components/public/StaticCompanyPage.js`, with only its relative CSS import relocated.

`/company` explicitly exports `dynamic = 'force-dynamic'`, so even a build made with the default static selector can start under CMS mode. One request-local React cache resolver returns source/content/fully validated metadata, and both page and metadata await it. Generic routes also validate metadata inside their cached resolver before body rendering. Successful publication and first-read-only snapshot checks require one API read, 404 requires one, and invalid configuration requires zero. Next 16.3.8 can start a fresh RSC error render and reread metadata after a generic throw; all-error paths are bounded to two reads and must retain hard500 with no content, including when the second read recovers. There is no cross-request content cache or proxy availability precheck.

The live route has no fixed static parameters. `scripts/build-preview.mjs` adds `generateStaticParams` and `dynamicParams = false` only to its disposable staging copy and sets `PAGES_SOURCE=static`, `PAGES_STATIC_PREVIEW=1` and `COMPANY_SOURCE=static`. It rejects CMS or invalid company selection before staging deletion/copy/replacement, and writes a minimal static company wrapper only into the disposable tree. This exports exactly `/pages/ru/about` from verbatim verified company text. `lib/public/pagesPreview.js` records the extracted static component source path, official source URL and review date; its dates are fixture provenance rather than CMS publication evidence.

Current local and hosted evidence is recorded in `docs/node-strapi-editorial-validation.md`; browser discovery is not browser execution. Optimistic Page conflicts/history and production readiness remain separate gaps.
